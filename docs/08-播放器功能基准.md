# 08 · 播放器功能基准（竞品对标 + 完整能力清单）

> 本文回答一个问题：**「播放器做到什么程度才算完善」**。
> 结论先行：Kanata 的播放器目标是 **「Infuse 的画质音频档次 + IINA/PotPlayer 的调节自由度 + 弹弹play 的弹幕深度」**，
> 三者交集正是目前市面上**没有任何一款产品同时做到**的位置。

---

## 1. 竞品扫描

### 1.1 Apple 生态播放器

| 产品 | 强项 | 弱项 | Kanata 要吸收的 |
| --- | --- | --- | --- |
| **Infuse** | 画质天花板：原生 Dolby Vision / Atmos 授权，色调映射精准；UI 最贴 Apple HIG；iCloud 进度同步；刮削体验好 | **没有弹幕**；可调项少（刻意做减法）；音频/字幕微调能力弱 | 画质档次、HDR 处理、UI 质感、iCloud 同步 |
| **VidHub** | 网盘直连（阿里/115/百度/123）；刮削快、中文识别率高；有弹幕 | 极端 HDR 原盘画质略逊 | 中文刮削策略、网盘接入 |
| **SenPlayer** | 跳过片头片尾最完善；AV1 硬解、8K；目录模式；**支持自定义弹幕 API**（弹弹play 接口规范） | UI 精致度一般 | 片头片尾方案、自定义弹幕 API 的接口约定 |
| **nPlayer** | 老牌万能格式；音轨/字幕调节丰富；有杜比授权 | UI 陈旧；弹幕能力弱 | 格式覆盖广度、音频调节项 |
| **Fileball** | 轻量、便宜、偏文件管理 | 更像文件管理器 | 目录模式直接播放 |
| **弹弹play**（Windows/Android） | 弹幕体验标杆：文件 hash 精准匹配、弹幕样式与屏蔽体系完整、开放弹幕网络 | Apple 端缺位 | **弹幕功能集全盘对标** |

### 1.2 桌面级播放器（能力上限参照）

| 产品 | 值得对标的能力 |
| --- | --- |
| **mpv / IINA** | ASS 特效字幕渲染最佳；视频/音频/字幕三大控制项直达；均衡器；逐帧步进；速度调节；在线字幕搜索；滤镜链 |
| **PotPlayer** | 逐帧播放、区域循环（A-B）、图形均衡器、声道混缩菜单、插帧、画面调节、书签 |
| **VLC** | 格式兜底能力、音视频/字幕同步微调（延迟）、网络协议覆盖（SMB/FTP/NFS/UPnP） |

### 1.3 结论：功能地图上的空白

```
         弹幕深度 ↑
弹弹play ●                          ◎ Kanata（目标位）
          │
 VidHub ● │ ● SenPlayer
          │
──────────┼────────────────────────────────→ 画质/音频/字幕专业度
          │            ● nPlayer      ● Infuse
                                      ● IINA/mpv（无弹幕、非 Apple 全端）
```

### 1.4 2026-09-01 实现差距复核

本轮重新核对 Infuse、VidHub、SenPlayer、Plex 与原需求后，不再把“能打开视频”视为播放器完成。当前能力与下一阶段边界如下：

| 能力域 | 当前已落地 | 仍需继续 |
| --- | --- | --- |
| 媒体库 | 本地文件/文件夹、HTTP/HLS、WebDAV、Jellyfin、Emby、Plex、Synology File Station；连接历史、在线状态、海报、目录/电影/剧集分类、合集队列、继续观看、收藏、搜索、筛选和排序 | QuickConnect、原生 SMB Range 桥、NFS/FTP、云盘、刮削编辑、离线下载 |
| 播放器 | AVPlayer 硬解、横屏全屏、全屏返回拦截、手势、锁定、PiP、AirPlay、0.25×–4×、音轨/内封字幕、队列循环、睡眠定时器、失败重试、按合集记忆片头片尾 | VLCKit/FFmpeg 格式兜底、软解切换、音频延迟与增益、逐帧、画面滤镜、Seek 缩略图、自动片头检测 |
| 字幕 | SRT/WebVTT/基础 ASS/SSA 手动导入，同名本地字幕自动关联，UTF-8/GB18030/Big5，±30 秒偏移 | libass 完整特效、PGS/VobSub/SUP、双字幕、样式覆盖、简繁转换、网络媒体同目录字幕 |
| 弹幕 | Bilibili/爱奇艺/腾讯/巴哈姆特内置来源，弹弹play与兼容网关回退，本地导入、缓存、手动重绑、字体/字号/透明度/描边/速度/区域/密度/屏蔽 | 芒果/优酷等来源、各来源独立偏移、正则与用户屏蔽、弹幕列表/密度曲线、跨设备同步 |
| 跨端 | iPhone/iPad 与 Apple TV 共用核心实现；Web 已完成本地视频与核心弹幕闭环 | CloudKit 进度/设置同步、Web 媒体服务器、Apple TV 实机 4K 与遥控器验收 |

执行顺序保持为：先保证媒体可访问、可续播和弹幕可兜底，再扩充解码格式与专业调节，最后补云同步、刮削与离线下载。原生 SMB、VLCKit/libass 和 CloudKit 都是独立工程，不用未经验证的占位实现冒充完成。

## 2. 完整能力清单

## 3. 三大同步项统一设计

播放器里有三个独立的时间偏移，必须用**同一套 UI 与记忆机制**，避免用户混淆：

| 项 | 范围 | 步进 | 记忆粒度 | 快捷入口 |
| --- | --- | --- | --- | --- |
| 音频延迟 | ±5s | 50ms | 单集 | 播放面板 → 音频 |
| 字幕延迟 | ±30s | 100ms | 单集 / 季 | 播放面板 → 字幕 |
| **弹幕延迟** | ±600s | 500ms | 单集 / 季 / 剧 / 全局，且**按来源独立** | 播放面板 → 弹幕（一步可达） |

弹幕范围之所以大出两个数量级：平台版本可能整体差一整段片头/广告（60–180s），甚至出现「本地是合集、平台是分集」的情况。
