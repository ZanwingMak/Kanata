## 2. 端差异的硬约束

### 2.1 tvOS：没有文件系统

Apple TV 不提供用户可见的文件系统与文件选择器，**所有片源必须来自网络协议**。因此：

- SMB / WebDAV / Jellyfin 在 tvOS 上是刚需，M1 必须完成；
- 文本输入极其痛苦（遥控器逐字输入服务器地址+密码），必须提供替代路径：
  1. 在 iPhone 上配置好源 → 经 iCloud 同步到 Apple TV（FR-SET-004）；
  2. tvOS 端显示配对二维码，手机端网页填写后推送；
  3. 支持 tvOS 的「用 iPhone 键盘输入」系统能力。
- tvOS 应用有更严格的存储与内存约束：本地缓存必须走 `Caches` 目录并接受系统清理，长视频弹幕分段加载而非一次性全量驻留。

### 2.2 Web：CORS 与编解码双重限制

- 浏览器**无法**直连 SMB / FTP / NFS / DLNA；
- WebDAV / Jellyfin / Alist 可用，但目标服务器必须允许跨域，否则需经 Kanata 网关做反向代理（网关提供 `/kanata/v1/proxy` 白名单代理，仅限用户自己配置的地址）；
- 编解码受浏览器限制：H.264/AAC 通用；HEVC 仅 Safari 与部分 Chrome；AV1 视浏览器而定；**不支持服务端转码**（FR-WEB-006），遇到不支持的编码直接提示改用 Apple 端；
- 本地文件走 File API，**不上传**，hash 在浏览器端用 Web Crypto 计算。

### 2.3 网络源的 hash 计算

弹弹play 的指纹需要**文件前 16MB 的 MD5**。网络源不能下载整文件：

| 源类型 | 取前 16MB 的方式 |
| --- | --- |
| HTTP/WebDAV/Alist | `Range: bytes=0-16777215` |
| SMB | 直接 seek + read（libdsm 支持） |
| Jellyfin/Emby/Plex | 走 `/Videos/{id}/stream?static=true` + Range |
| 不支持 Range 的源 | 降级为「文件名 + 时长」匹配（`matchMode: fileNameOnly`） |

## 3. 媒体服务器接入要点

### 3.1 Jellyfin（推荐首选）

```
认证：POST /Users/AuthenticateByName  { Username, Pw }
      → AccessToken，后续请求头 Authorization: MediaBrowser Token="..."
媒体库：GET /Users/{userId}/Views
剧集：  GET /Shows/{seriesId}/Episodes?userId=&seasonId=
条目：  GET /Users/{userId}/Items/{itemId}   → MediaSources（编码/音轨/字幕轨）
播放：  GET /Videos/{itemId}/stream?static=true&api_key=   （直连原始文件，不转码）
进度：  POST /Sessions/Playing/Progress     （回写观看进度）
```

优势：自带刮削元数据（剧名/季/集/海报），可直接喂给弹幕匹配，**跳过文件名解析这一最大误差源**。因此媒体服务器路径的匹配准确率显著高于裸文件路径。

### 3.2 Emby / Plex

- Emby 接口与 Jellyfin 高度同构，可共用一套抽象，差异集中在认证头与少量字段名；
- Plex 使用 `X-Plex-Token`，媒体树走 `/library/sections`，条目走 `/library/metadata/{id}`，播放走 `/library/parts/{id}/file`。

### 3.3 Synology DSM

```
登录：GET /webapi/entry.cgi?api=SYNO.API.Auth&version=6&method=login&account=&passwd=&session=FileStation&format=sid
      （启用 2FA 时需 otp_code，UI 上要有输入框）
列目录：api=SYNO.FileStation.List&method=list&folder_path=
下载/流：/webapi/entry.cgi?api=SYNO.FileStation.Download&method=download&path=&mode=open&_sid=
```
Video Station 另有独立 API，可提供海报与元数据，作为可选增强。

## 4. 文件名解析（FR-LIB-002）

裸文件源没有元数据，解析质量直接决定弹幕匹配成功率。

### 4.1 解析流程

```
原始文件名
 → ① 剥离扩展名、[发布组]、【字幕组】、(年份) 等括号块（先记录再剥离）
 → ② 提取分辨率(1080p/2160p/4K)、编码(x264/HEVC/AV1)、来源(BDRip/WEB-DL)、音频(FLAC/AAC)
 → ③ 提取季集：S01E02 / 第01季第02集 / 1x02 / [02] / - 02 / EP02 / 第02话
 → ④ 剩余部分归一化为标题：去多余分隔符、全半角统一、简繁保留双版本
 → ⑤ 输出 ParsedTitle，并给出置信度
```

### 4.3 解析失败的兜底

1. 用父目录名补充剧名（`.../葬送的芙莉莲/S01/12.mkv`）；
2. 用媒体服务器元数据覆盖（Jellyfin/Emby/Plex 路径优先级最高）；
3. 都失败 → 走用户手动搜索绑定（FR-MATCH-003），且结果持久化（FR-MATCH-007）。

## 5. 播放 URL 解析优先级

```
1. 媒体服务器直连原始文件（static=true）      ← 最优，保留全部音轨字幕轨
2. 源协议原生 URL（smb:// webdav:// ftp://）  ← 交给 VLCKit
3. HTTP 直链（含 Range 支持）
4. 媒体服务器转码流（HLS）                    ← 仅在前三者失败时使用，会丢失多轨
```

**禁止**：为省事默认走服务器转码。转码会丢失音轨/字幕轨并降低画质，与 `08` 文档的播放器定位冲突。

## 6. 源健康与诊断（FR-IMP-015）

每个源的失败必须落到具体分类，UI 文案给出可执行建议：

| 错误码 | 分类 | 建议文案 |
| --- | --- | --- |
| SRC-1001 | 网络不可达 | 检查设备是否与 NAS 在同一网络 |
| SRC-1002 | 认证失败 | 账号或密码有误，请重新输入 |
| SRC-1003 | 路径不存在 | 共享名或目录已变更 |
| SRC-1004 | 协议不支持 | 该平台不支持此协议（如 Web 端 SMB） |
| SRC-1005 | 证书不受信任 | 自签证书需手动信任 |
| SRC-1006 | 服务器版本不兼容 | 提示最低支持版本 |
| SRC-1007 | 权限不足 | 该账号无此目录读取权限 |
| SRC-1008 | 超时 | 网络较慢，可调大超时时间 |

**不允许出现「未知错误」作为最终态**：无法归类时输出 `SRC-1999` 并附带原始错误摘要，供用户上报。
