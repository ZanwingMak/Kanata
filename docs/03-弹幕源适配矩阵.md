# 03 · 弹幕源适配矩阵

> ⚠️ 本文描述的均为各平台**公开可访问的弹幕数据接口**，用于个人观看场景下的弹幕获取。
> 所有接口都是非官方承诺的内部接口，**随时可能变更**。每个适配器都必须实现 `healthCheck()`，
> 并由 CI 每日探活（见 `05` 文档 §7）。
> 使用约束与红线见 `07-合规与风险.md`。
>
> **最后验证日期**列由改动适配器的人负责更新（CLAUDE.md 第 16 条）。

## 1. 弹弹play 开放平台（默认主力源）

- Base：`https://api.dandanplay.net`
- 认证（二选一）：
  - **签名模式**（客户端）：`X-AppId`、`X-Timestamp`（Unix 秒）、`X-Signature = base64(sha256(AppId + Timestamp + Path + AppSecret))`。
    ⚠️ 签名用的 `Path` **不含域名与 query**，例如 `/api/v2/comment/123450001`。
  - **凭证模式**（服务端）：`X-AppId`、`X-AppSecret`。
- 关键接口：`/api/v2/match`（文件识别）、`/api/v2/search/episodes`、`/api/v2/comment/{episodeId}?withRelated=true`、`/api/v2/bangumi/{animeId}`。
- 使用约束：**禁止商业使用、批量抓取、规模下载**；官方建议对返回数据缓存 2–24 小时；高频调用会被限流。
- 适配要点：
  1. `withRelated=true` 会带回其他站点关联弹幕，是「多源」的最低成本入口；
  2. `shift` 字段是官方给出的时轴修正，必须应用到 `DanmakuItem.time`；
  3. AppId/AppSecret 需要向官方申请，**不得硬编码进开源仓库**，走环境变量或用户自填。

文档：<https://doc.dandanplay.com/open/>

## 2. 哔哩哔哩

### 2.1 取弹幕

| 步骤 | 接口 | 说明 |
| --- | --- | --- |
| 1. 定位视频 | `GET https://api.bilibili.com/x/web-interface/view?bvid={bvid}` | 取 `cid`、`duration`、`pages[]`（多 P） |
| 1'. 番剧 | `GET https://api.bilibili.com/pgc/view/web/season?season_id={ssid}`（或 `ep_id`） | 取 `episodes[].cid`、`episodes[].long_title` |
| 2. 拉弹幕分片 | `GET https://api.bilibili.com/x/v2/dm/web/seg.so?type=1&oid={cid}&segment_index={i}` | **每片 360 秒**，`i` 从 1 到 `ceil(duration/360)` |
| 3. 解析 | protobuf `bilibili.community.service.dm.v1.DmSegMobileReply` | `elems[]`：`progress`(ms)、`mode`、`fontsize`、`color`、`midHash`、`content`、`ctime` |
| 备用 | `GET https://comment.bilibili.com/{cid}.xml` | 仅返回抽样弹幕，**只作兜底** |
| 历史弹幕 | `GET https://api.bilibili.com/x/v2/dm/web/history/seg.so?type=1&oid={cid}&date=YYYY-MM-DD` | 需完整 Cookie |

请求头必须带：`User-Agent`（桌面浏览器 UA）、`Referer: https://www.bilibili.com`。

### 2.2 搜索与匹配

- 搜索：`GET https://api.bilibili.com/x/web-interface/search/type?search_type=media_bangumi&keyword={kw}`
- ⚠️ **WBI 签名**：B 站 Web 搜索类接口需要 `w_rid` + `wts` 的 WBI 签名，且需先拿 `buvid3`（访问首页或 `https://api.bilibili.com/x/frontend/finger/spi`）。适配器需实现 WBI 混淆密钥的获取与缓存（密钥每日更新）。
- 剧集号映射：番剧用 `season` 接口的 `episodes[].title`（多为数字集号）对齐本地集号；影视用 `duration` 做二次校验。

### 2.3 登录（FR-AUTH-001）

**扫码登录（推荐，四端通用）**

```
1) GET https://passport.bilibili.com/x/passport-login/web/qrcode/generate
   → { url, qrcode_key }            // url 用于生成二维码
2) 每 2s 轮询：
   GET https://passport.bilibili.com/x/passport-login/web/qrcode/poll?qrcode_key={key}
   code: 86101 未扫描 / 86090 已扫描待确认 / 86038 已失效 / 0 成功
3) code=0 时，从响应的 Set-Cookie 取：
   SESSDATA、bili_jct、DedeUserID、sid  → 存入 Keychain
4) 校验：GET https://api.bilibili.com/x/web-interface/nav → 返回昵称/头像/isLogin
```

- tvOS 上二维码显示在电视屏幕，用户手机 App 扫码；轮询超时 180s 后提示刷新。
- Cookie 有效期约 30 天，`SESSDATA` 失效时 `nav` 返回 `isLogin=false` → 触发 FR-AUTH-003 提示。
- 也支持手动粘贴 Cookie（FR-AUTH-002），供不便扫码的场景使用。

### 2.4 无凭证时的差异

| 场景 | 无 Cookie | 有 Cookie |
| --- | --- | --- |
| 普通视频弹幕 | 部分返回 | 完整 |
| 番剧弹幕 | 部分/受限 | 完整 |
| 港澳台限定内容 | 不可用 | 视账号地区而定 |
| 历史弹幕 | 不可用 | 可用 |

参考：[bilibili-API-collect · protobuf 弹幕](https://github.com/SocialSisterYi/bilibili-API-collect/blob/master/docs/danmaku/danmaku_proto.md)

## 3. 爱奇艺

| 步骤 | 接口 / 规则 |
| --- | --- |
| 搜索 | `GET https://search.video.iqiyi.com/o?if=html5&key={keyword}&pageNum=1&pageSize=20` |
| 取 tvid | 播放页 HTML 中的 `page-info`（含 `tvId`、`albumId`、`cid`、`duration`、`tvName`）；或 `GET https://pcw-api.iqiyi.com/video/video/baseinfo/{tvid}` |
| 分集列表 | `GET https://pcw-api.iqiyi.com/albums/album/avlistinfo?aid={albumId}&page=1&size=50` |
| 弹幕 | `GET https://cmts.iqiyi.com/bullet/{A}/{B}/{tvid}_300_{page}.z` |

**路径分桶规则**（必须严格实现）：
```
s = str(tvid)
A = s[-4:-2]     // 倒数第 4、3 位
B = s[-2:]       // 倒数第 2、1 位
page 从 1 递增，每片覆盖 300 秒；总片数 = ceil(duration / 300)
```

**解压**：响应为 zlib/gzip 压缩体，用 `zlib.decompressobj(32 + MAX_WBITS)`（Node 侧用 `zlib.gunzipSync` 或 `inflateSync` 双路 fallback）解出 **XML**。

**字段映射**：`showTime` → time（秒）；`color` 为十六进制字符串，需转十进制；`content` → 内容；`uid` → senderHash。

**注意**：某集的最大分片数不固定，遇到 404 或空体即停止；不要按固定次数循环。

## 4. 腾讯视频

| 步骤 | 接口 |
| --- | --- |
| 取 vid | 播放页 HTML 中的 `VIDEO_INFO`（含 `vid`、`duration`、`title`）；或从 URL `/x/cover/{cid}/{vid}.html` 解析 |
| 分集列表 | `POST https://pbaccess.video.qq.com/trpc.universal_backend_service.page_server_rpc.PageServer/GetPageData`（cid → 分集 vid 列表） |
| 弹幕索引 | `GET https://dm.video.qq.com/barrage/base/{vid}` → `segment_index`：`{ "0": { segment_start, segment_name }, "30000": {...} }` |
| 弹幕分片 | `GET https://dm.video.qq.com/barrage/segment/{vid}/{segment_name}` → `barrage_list[]` |

**字段映射**：`time_offset`(ms) → time；`content` → 内容；`content_style`（JSON 字符串）中可能含颜色与位置，缺省按 mode=1、白色处理；`vuid` → senderHash。

**注意**：
- 索引 key 是毫秒起点，必须**按索引遍历**而不是自己推算分片名；
- 旧接口 `bullet.video.qq.com/fcgi-bin/target/regist` + `mfm.video.qq.com/danmu` 已基本废弃，仅作兜底；
- 请求需带 `Referer: https://v.qq.com/` 与桌面 UA。

## 5. 芒果 TV

```
URL 形如 https://www.mgtv.com/b/{cid}/{vid}.html
弹幕：GET https://galaxy.bz.mgtv.com/rdbarrage?vid={vid}&cid={cid}&time={ms}
```
- `time` 从 0 开始，**下一个 time 取自上一次响应中的 `next` 字段**，直到 `next` 为 0 或超过视频时长；
- 字段：`data.items[].time`(ms) → time，`content` → 内容，`uid` → senderHash；
- 无需登录，是几个平台里最简单的。

## 6. 优酷（易失效，需重点监控）

走阿里 MTOP 网关，是所有源里最脆弱的一条链路：

```
1) GET https://log.mmstat.com/eg.js      → Cookie 中获得 _m_h5_tk（形如 "token_时间戳"）、_m_h5_tc
2) token = _m_h5_tk.split('_')[0]
3) appKey = 24679788
4) data = JSON.stringify({
     pid: 0, ctype: 10004, sver: "3.1.0", cver: "v1.0",
     ctime: <ms>, guid: <cna>, vid: <vid>, mat: <第几分钟>, mcount: 1, type: 1,
     msg: base64(<内层 msg JSON>), sign: md5(<内层 msg JSON> + MAC_SECRET)
   })
5) sign = md5(token + "&" + t + "&" + appKey + "&" + data)
6) POST https://acs.youku.com/h5/mopen.youku.danmu.list/1.0/?jsv=2.5.1&appKey=24679788&t={t}&sign={sign}&api=mopen.youku.danmu.list&v=1.0&type=originaljson&dataType=json
   body: data={urlencode(data)}
7) 响应 data.result 为 JSON 字符串，内含 result[] 弹幕数组
```
- 分片粒度：`mat` 每次 1 分钟，需循环 `ceil(duration/60)` 次；
- 字段：`playat`(ms) → time，`content` → 内容，`propertis` 内含 color/pos；
- **降级策略**：任一步失败即整源降级，前端提示「优酷源暂不可用」，不阻塞其他源（FR-DMK-013）。

## 7. 巴哈姆特动画疯（可选）

- 取 sn：动画播放页 URL `https://ani.gamer.com.tw/animeVideo.php?sn={sn}`
- 弹幕：`POST https://ani.gamer.com.tw/ajax/danmuGet.php`，body `sn={sn}`，返回 JSON 数组（`text`、`time`(1/10 秒)、`color`、`position`）
- 繁中内容为主，适合日番；匹配需借助 TMDB 做中日繁标题归一。

## 8. 自定义兼容 API（兜底与生态互通）

用户可在设置中填入任意**弹弹play 接口规范兼容**的服务地址（FR-DMK-007），典型如社区项目 [`huangxd-/danmu_api`](https://github.com/huangxd-/danmu_api) 的自部署实例：

```
GET {base}/{token}/api/v2/search/anime?keyword=…
GET {base}/{token}/api/v2/comment/{commentId}?format=json
GET {base}/{token}/api/v2/comment?url={视频播放页URL}
```

这条通道的价值：
1. 用户已有实例可直接复用，零迁移成本；
2. Kanata 自己的网关也对外提供同一套接口，**双向兼容**——Kanata 网关可以填进 Senplayer/EPlayerX，第三方实例也能填进 Kanata；
3. 当某个内置适配器失效时，用户可临时切到社区实例，不必等版本更新。

## 9. 适配器工程规范（强制）

1. **统一出口**：所有适配器实现 `DanmakuProvider`（见 `02` 文档 §4.1），不得在路由/业务层写平台分支。
2. **请求上下文注入**：UA、Referer、超时（默认 8s）、重试（最多 2 次，指数退避）、代理由 `ctx.fetch` 统一提供，适配器不自己 new HTTP 客户端。
3. **分片并发**：单集分片并发上限 5，整源总并发上限 10，避免触发风控。
4. **结构变更检测**：解析前先做**轻量结构断言**（关键字段存在性）；断言失败抛 `50301`，并把响应前 512 字节写入诊断日志（脱敏后）。
5. **凭证隔离**：凭证只从 `ctx.credential` 读取，禁止落盘、禁止进缓存键、禁止进日志。
6. **探活用例**：每个适配器附带 1 条真实剧集的 `healthCheck`，CI 每日执行（`05` 文档 §7）。
7. **失败即降级**：任一源失败不得抛出到主流程，统一转成 `degraded[]` 返回。
8. 修改适配器后，**必须更新本文 §0 表格的「最后验证日期」**。
