# 09 · 开发记录与功能计划

本文件同时记录已经落地的功能和后续计划。每次功能实现必须在同一轮追加记录，并更新计划状态；不得把未验证的功能标记为完成。

## 记录规则

- 每条记录包含日期、需求 ID、实现内容、关键文件、验证结果和已知限制。
- 状态只使用：`计划中`、`开发中`、`已实现`、`受阻`。
- 功能完成以构建或可重复的运行验证为准；仅写入代码但未验证时仍标记为 `开发中`。
- 外部平台能力必须记录最后验证日期和当时的配额、权限或协议限制。

### 运行时兜底顺序

1. 读取用户已确认绑定，优先检查本地导入弹幕和持久化缓存。
2. 按绑定来源取在线弹幕；失败或空数据时读取旧缓存并标记降级。
3. 并行查询已启用的直接平台 Provider，按匹配置信度、时长差、弹幕数量、近期成功率和延迟排序。
4. 直接来源没有结果时访问自定义兼容 API 池；默认顺序回退，用户可选有限竞速或聚合。
5. 再查询 Kanata 自建共享弹幕库与弹弹play可用结果；它们都只是可选 Provider。
6. 仍未命中时自动打开关键词搜索，同时允许粘贴播放页 URL、导入本地弹幕文件或暂时无弹幕播放。
7. 用户确认后保存视频指纹、作品/季/集、来源实例、平台剧集 ID、偏移和缩放；下一次从第 1 步直接复用。

| [TMDB API](https://developer.themoviedb.org/docs/finding-data) | 电视剧、电影搜索和外部 ID 关联 | 需要 API 凭证并遵守其条款；动画季集结构可能与文件命名不一致 | 计划用于非动画内容和媒体服务器元数据补全 |
| [AniList API](https://anilist.gitbook.io/anilist-apiv2-docs/docs/guide/rate-limiting) | 动画多语言标题与 MAL ID | 当前降级额度为 30 次/分钟；禁止把 API 当备份数据库或批量囤积数据 | 暂不作为首选，只做可选别名补充 |
| [danmu_api](https://github.com/huangxd-/danmu_api) | 弹弹play兼容聚合服务，覆盖爱优腾芒哔、咪咕、搜狐、乐视、西瓜、巴哈姆特等 | 来源质量和稳定性各异；实例配置差异较大 | 作为自定义 API 池的兼容性参考和用户自部署选项，不与 Kanata 内置 Provider 耦合 |
| [bilibili-api-collect-mirror](https://github.com/alittlehuaji/bilibili-api-collect-mirror) | Bilibili Protobuf、WBI 和接口字段历史资料 | 2026-01-22 后没有持续维护；不能作为接口稳定性证明 | 仅用于核对历史行为；实际可用性由 Kanata 探活与真实响应决定 |

任何元数据服务都不能替代弹幕数据。本项目不通过批量抓取复制第三方数据库。
