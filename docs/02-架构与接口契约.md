**依赖方向（禁止反向）**：`App(UI) → KanataCore → Gateway API`；`KanataRender` 不依赖任何业务模块，只接收弹幕数组与时间。

## 2. 统一数据模型

### 2.1 弹幕

```ts
/** 统一弹幕条目：所有平台数据归一化后的唯一形态 */
interface DanmakuItem {
  id: string;            // 稳定唯一 ID，格式：`${source}:${platformId}`
  time: number;          // 相对视频起点的秒数（float，已应用平台侧修正）
  mode: DanmakuMode;     // 显示模式
  fontSize: number;      // 平台原始字号（25 为标准），渲染端做归一化
  color: number;         // RGB 十进制，16777215 = 白
  content: string;       // 文本内容（已做长度与控制字符清洗）
  source: DanmakuSourceId;
  senderHash?: string;   // 用户 hash，用于「屏蔽此用户」
  createdAt?: number;    // Unix 秒，用于按时间过滤
  pool?: 0 | 1 | 2;      // 0普通 1字幕池 2特殊
  weight?: number;       // 0-10，密度限流时的保留优先级
  dupCount?: number;     // 去重后合并的条数，用于「×N」显示
}

/** 1滚动 4底部 5顶部 6逆向；7(高级)/8(代码) 解析阶段丢弃 */
type DanmakuMode = 1 | 4 | 5 | 6;

type DanmakuSourceId =
  | 'dandanplay' | 'bilibili' | 'iqiyi' | 'qq' | 'youku'
  | 'mgtv' | 'bahamut' | 'local' | 'custom';
```

**平台字段映射规则**（适配器必须遵守）：

| 平台 | time | mode | color | senderHash |
| --- | --- | --- | --- | --- |
| bilibili (protobuf) | `progress / 1000` | `mode` 直接映射，3→1 | `color` | `midHash` |
| dandanplay | `p` 第 1 段 | `p` 第 2 段 | `p` 第 3 段 | `p` 第 4 段(uid) |
| iqiyi | `showTime` | 固定 1（除非有 `position`） | 十六进制转十进制 | `userInfo.uid` |
| qq | `time_offset / 1000` | `content_style` 有则解析，默认 1 | 样式色值 | `vuid` |
| youku | `playat / 1000` | `propertis.pos` 映射 | `propertis.color` | `uid` |
| mgtv | `time / 1000` | 固定 1 | 默认白 | `uid` |

### 2.2 媒体与识别

```ts
/** 一个可播放条目 */
interface MediaItem {
  id: string;              // 本地稳定 ID
  sourceId: string;        // 所属媒体源
  path: string;            // 源内路径或服务器 itemId
  displayName: string;
  fileSize?: number;
  duration?: number;       // 秒
  container?: string;
  videoCodec?: string;
  audioTracks?: TrackInfo[];
  subtitleTracks?: TrackInfo[];
  parsed?: ParsedTitle;    // 文件名解析结果
  metadata?: MediaMetadata;// 刮削结果
  binding?: DanmakuBinding;// 已确认的弹幕绑定
}

interface ParsedTitle {
  title: string; season?: number; episode?: number;
  year?: number; resolution?: string; group?: string;
}

/** 弹幕识别指纹（弹弹play 规范） */
interface MediaFingerprint {
  fileName: string;        // 不含扩展名
  fileHash: string;        // 前 16MB 的 MD5（小写十六进制）
  fileSize: number;
  videoDuration: number;   // 秒，取整
}

/** 用户/系统确认的弹幕来源绑定，持久化并跨端同步 */
interface DanmakuBinding {
  mediaItemId: string;
  entries: Array<{
    source: DanmakuSourceId;
    platformEpisodeId: string;   // 平台侧剧集标识（cid / tvid / vid …）
    title: string;
    offset: number;              // 秒，该来源独立偏移
    scale?: number;              // 时长比缩放，默认 1
    enabled: boolean;
    confirmedByUser: boolean;
  }>;
}
```

### 2.3 时轴

```ts
/** 偏移解析优先级：episode > season > series > global */
interface OffsetRule {
  scope: 'global' | 'series' | 'season' | 'episode';
  key: string;             // series/season/episode 的标识
  source?: DanmakuSourceId;// 为空表示对所有来源生效
  offset: number;          // 秒，正=弹幕延后
  scale: number;           // 默认 1.0
}

/** 最终时间换算：displayTime = item.time * scale + offset */
```

## 3. 网关 API 契约

Base：`{gatewayBase}/{token}`（路径 Token，兼容弹弹play 生态习惯）或 `Authorization: Bearer {token}`。

### 3.1 弹弹play v2 兼容组

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v2/search/anime?keyword=` | 按关键词搜索作品 |
| GET | `/api/v2/search/episodes?anime=&episode=` | 搜索作品及分集 |
| POST | `/api/v2/match` | 文件指纹匹配，body 见下 |
| GET | `/api/v2/bangumi/:animeId` | 作品详情与分集列表 |
| GET | `/api/v2/comment/:episodeId?withRelated=true&chConvert=0` | 取弹幕（弹弹play 格式） |

```ts
// POST /api/v2/match
interface MatchRequest {
  fileName: string; fileHash: string; fileSize: number; videoDuration: number;
  matchMode?: 'hashAndFileName' | 'fileNameOnly' | 'hashOnly';
}
interface MatchResponse {
  isMatched: boolean;
  matches: Array<{
    episodeId: number; animeId: number;
    animeTitle: string; episodeTitle: string;
    type: string; shift: number;
  }>;
  errorCode: number; success: boolean; errorMessage: string;
}

// GET /api/v2/comment/:episodeId 响应（弹弹play 格式）
interface CommentResponse {
  count: number;
  comments: Array<{
    cid: number;
    p: string;   // "时间(秒),模式,颜色,用户ID"
    m: string;   // 内容
  }>;
}
```

> 兼容性要求：该组接口的响应必须能被 Senplayer / EPlayerX 等第三方播放器直接消费。字段不得增删，扩展信息一律走 `/kanata/v1/*`。

### 3.2 Kanata 扩展组

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/kanata/v1/health` | 存活与版本 |
| GET | `/kanata/v1/sources` | 各平台适配器可用性与最近探活结果 |
| POST | `/kanata/v1/resolve` | 跨平台剧集映射，返回候选 |
| GET | `/kanata/v1/danmaku` | 取统一模型弹幕（支持多源聚合、去重、偏移） |
| POST | `/kanata/v1/credential/verify` | 校验平台凭证有效性 |
| GET | `/kanata/v1/density` | 弹幕密度曲线（1Hz 采样），供自动对齐使用 |

```ts
// POST /kanata/v1/resolve
interface ResolveRequest {
  title: string; season?: number; episode?: number;
  duration?: number;                 // 秒，用于时长校验
  year?: number;
  sources?: DanmakuSourceId[];       // 为空表示全部启用源
  fingerprint?: MediaFingerprint;    // 有则优先走精确匹配
}
interface ResolveResponse {
  candidates: Array<{
    source: DanmakuSourceId;
    platformEpisodeId: string;
    title: string; episodeTitle?: string;
    duration?: number;
    confidence: number;              // 0-1，综合标题相似度与时长差
    danmakuCount?: number;
  }>;
  degraded: DanmakuSourceId[];       // 本次不可用的源
}

// GET /kanata/v1/danmaku?refs=bilibili:123,iqiyi:456&dedup=true&offsets=bilibili:-12.5
interface DanmakuResponse {
  items: DanmakuItem[];
  stats: {
    total: number;
    bySource: Record<DanmakuSourceId, number>;
    deduped: number;
    elapsedMs: number;
  };
  degraded: Array<{ source: DanmakuSourceId; reason: string; code: number }>;
}

// GET /kanata/v1/sources
interface SourcesResponse {
  sources: Array<{
    id: DanmakuSourceId;
    available: boolean;
    requiresCredential: boolean;
    hasCredential: boolean;
    lastCheckedAt: number;
    lastError?: string;
    avgLatencyMs?: number;
  }>;
}
```

### 3.3 凭证透传

客户端在需要凭证的请求上附带：

```
X-Kanata-Credential: <base64(JSON)>    // 见下，仅单次请求内使用
X-Kanata-Credential-Enc: aes-256-gcm   // 传输层已是 HTTPS 时可为 none
```

```ts
interface CredentialPayload {
  bilibili?: { SESSDATA: string; bili_jct?: string; DedeUserID?: string; buvid3?: string };
  // 其他平台按需扩展
}
```

**硬性约束**：网关收到凭证后只允许在当次请求的内存生命周期内使用，**禁止写入日志、缓存键、持久化存储**（FR-GW-010 / NFR-SEC-002）。

### 3.4 错误码

| Code | 含义 | 客户端行为 |
| --- | --- | --- |
| 0 | 成功 | — |
| 40001 | 参数缺失/非法 | 提示并中止 |
| 40101 | Token 无效 | 引导检查网关设置 |
| 40301 | 平台需要凭证 | 引导登录（FR-AUTH-001） |
| 40302 | 凭证已失效 | 提示重新登录 |
| 40401 | 未匹配到剧集 | 降级为搜索选择（FR-MATCH-003） |
| 42901 | 平台限流 | 退避重试，提示稍后 |
| 50001 | 适配器内部错误 | 标记该源降级，继续其余源 |
| 50301 | 平台接口结构变更 | 上报诊断，标记该源不可用 |
| 50401 | 平台请求超时 | 同上 |

## 4. 客户端接口抽象

### 4.1 弹幕源（网关侧适配器）

```ts
/**
 * 平台适配器统一接口。新增平台只需实现本接口并在 registry 注册，
 * 不得在路由层或业务层出现平台专有分支。
 */
interface DanmakuProvider {
  readonly id: DanmakuSourceId;
  readonly requiresCredential: boolean;

  /** 按标题/季/集检索平台侧候选剧集 */
  search(query: ResolveRequest, ctx: ProviderContext): Promise<ProviderCandidate[]>;

  /** 拉取指定剧集的全量弹幕（内部负责分片、解压、解码） */
  fetch(platformEpisodeId: string, ctx: ProviderContext): Promise<DanmakuItem[]>;

  /** 用文件指纹做精确匹配。仅支持 hash 匹配的平台实现此方法（目前只有弹弹play） */
  match?(fingerprint: MediaFingerprint, ctx: ProviderContext): Promise<ProviderCandidate[]>;

  /** 由播放页 URL 直接解析出剧集 ID（供「粘贴链接」入口使用） */
  parseUrl?(url: string): string | null;

  /** 探活：CI 每日调用，验证接口结构未变 */
  healthCheck(ctx: ProviderContext): Promise<HealthResult>;
}

interface ProviderContext {
  credential?: CredentialPayload;
  fetch: FetchLike;      // 已注入代理、超时、重试、UA/Referer
  logger: Logger;        // 自动脱敏
  signal: AbortSignal;
}
```

### 4.2 媒体源（客户端侧）

```ts
/** 所有片源类型（本地/SMB/WebDAV/Jellyfin/...）统一接口 */
interface MediaSourceProvider {
  readonly id: string;
  readonly kind: 'local' | 'smb' | 'webdav' | 'ftp' | 'jellyfin' | 'emby' | 'plex' | 'dsm' | 'alist' | 'dlna' | 'http';
  connect(): Promise<void>;
  list(path: string): Promise<MediaEntry[]>;
  /** 返回可直接交给播放内核的 URL 或流句柄 */
  resolvePlayback(item: MediaEntry): Promise<PlaybackSource>;
  /** 读取字节区间，用于计算前 16MB hash（网络源走 Range 请求） */
  readRange(item: MediaEntry, offset: number, length: number): Promise<Uint8Array>;
  disconnect(): Promise<void>;
}
```

### 4.3 播放内核（Apple 端）

```swift
/// 播放内核统一抽象。AVPlayer 与 VLCKit 各实现一份，
/// 上层 UI 与弹幕引擎只依赖本协议，不感知具体内核。
protocol PlaybackEngine: AnyObject {
    var currentTime: TimeInterval { get }      // 当前播放位置
    var duration: TimeInterval { get }
    var rate: Float { get set }                // 倍速，变速不变调
    var audioTracks: [TrackInfo] { get }
    var subtitleTracks: [TrackInfo] { get }
    var audioDelay: TimeInterval { get set }   // FR-PLY-203
    var subtitleDelay: TimeInterval { get set }// FR-PLY-304
    var statistics: PlaybackStats { get }      // 码率/帧率/解码方式，供信息面板

    func load(_ source: PlaybackSource) throws
    func play(); func pause()
    func seek(to time: TimeInterval, completion: @escaping (Bool) -> Void)
    func selectAudioTrack(_ id: String); func selectSubtitleTrack(_ id: String?)
    func stepFrame(forward: Bool)              // FR-PLY-110

    var delegate: PlaybackEngineDelegate? { get set }
}
```

### 4.4 弹幕渲染引擎

```swift
/// 渲染引擎只接收「弹幕数组 + 时间源 + 配置」，不做网络与业务。
/// 时间由 CADisplayLink 驱动，在内核时间回调之间做插值，避免抖动。
protocol DanmakuRenderer: AnyObject {
    func load(items: [DanmakuItem])                 // 一次性装载全片弹幕
    func update(config: DanmakuRenderConfig)        // 字号/透明度/区域/速度等
    func sync(time: TimeInterval, rate: Float)      // 播放器时间与倍速
    func reset()                                    // seek / 切集时调用
    func setMask(_ mask: CGImage?)                  // 弹幕蒙版，可为 nil
}

struct DanmakuRenderConfig {
    var fontScale: Double        // 0.5 – 2.0，FR-DMK-103
    var opacity: Double          // 0.1 – 1.0
    var displayArea: DisplayArea // 1/4、1/2、3/4、全屏、仅顶、仅底
    var scrollDuration: Double   // 3 – 15s 穿屏
    var maxTracks: Int
    var lineSpacing: Double
    var fontName: String?
    var bold: Bool
    var strokeWidth: Double
    var densityLimit: Int        // 同屏上限
    var mergeDuplicates: Bool
    var modeFilter: Set<DanmakuMode>
    var blockRules: [BlockRule]
}
```

## 5. 缓存规范

| 层 | 键格式 | TTL | 说明 |
| --- | --- | --- | --- |
| 网关 · 搜索 | `search:{source}:{sha1(query)}` | 6h | |
| 网关 · 弹幕 | `dm:{source}:{episodeId}:{v}` | 12h（可配 2–24h） | 遵守弹弹play 缓存建议 |
| 网关 · 探活 | `health:{source}` | 5min | |
| 客户端 · 弹幕 | SQLite 表 `danmaku_cache(mediaId, source, payload, fetchedAt)` | 7d | 支持离线观看 |
| 客户端 · 元数据 | `meta:{tmdbId}` | 30d | |

**缓存键中禁止出现任何凭证或用户标识。**

## 6. 关键流程时序

```
播放一集的完整链路：

App                    KanataCore                Gateway              平台
 │  打开条目             │                          │                   │
 ├─────────────────────►│ 读取 binding？            │                   │
 │                      │  有 → 直接取弹幕          │                   │
 │                      │  无 ↓                     │                   │
 │                      ├─ 计算指纹(前16MB MD5) ───►│ POST /api/v2/match│
 │                      │                          ├──────────────────►│ 弹弹play
 │                      │◄── isMatched=false ──────┤                   │
 │                      ├─ POST /kanata/v1/resolve ►│ 多平台并发检索     │
 │                      │                          ├──────────────────►│ B站/爱奇艺/…
 │                      │◄── candidates ───────────┤                   │
 │◄─ 展示候选（如需） ───┤                          │                   │
 │  用户确认 → 写 binding│                          │                   │
 │                      ├─ GET /kanata/v1/danmaku ─►│ 拉取+归一+去重+偏移│
 │                      │◄── DanmakuItem[] ────────┤                   │
 │◄─ renderer.load() ───┤                          │                   │
 │  播放，displayLink 驱动渲染，sync(time, rate)     │                   │
```

## 7. 给接手 AI 的实现顺序建议

1. `gateway`：先搭 Fastify + registry + `dandanplay` 适配器 → 打通 `/api/v2/*`；
2. `KanataCore`：指纹计算 + 网关客户端 + 本地文件源；
3. `KanataRender`：先用 CoreAnimation 实现可跑通版本，性能不达标再换 Metal；
4. `KanataApp`：最小播放页（AVPlayer + 弹幕层）→ 验证 M0；
5. 之后按里程碑铺开源适配器与端。

每步交付都必须更新对应 `FR-*` 的状态与 `05` 文档中的用例执行结果。
