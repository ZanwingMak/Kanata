# 07 · 合规与风险

> 本文不构成法律意见。它定义**项目自我约束的工程红线**，以及已识别风险的应对方式。
> 涉及实际发行、商业化前，建议由专业法务复核。

---

## 1. 产品法律定位

Kanata 是一个**播放器工具**：

1. **不提供任何影视内容**——媒体全部来自用户自己的设备、NAS 或用户自建的媒体服务器；
2. **不解析、不下载、不播放第三方平台的视频流**；
3. 只获取各平台**公开可访问的弹幕（用户评论）数据**，用于用户个人的观看体验；
4. 不做内容分发、不做资源搜索、不做种子/网盘公共索引。

---

## 2. 红线清单（明确不做）

| 编号 | 不做的事 | 原因 |
| --- | --- | --- |
| RL-01 | 视频流解析 / VIP 内容解析 / 去广告解析 | 直接侵害平台权益，法律风险最高 |
| RL-02 | DRM（FairPlay/Widevine 等）绕过 | 多法域明确违法 |
| RL-03 | 代理登录、账号密码代填、账号共享 | 账号安全与平台协议 |
| RL-04 | 规模化爬取、弹幕数据转售、公开弹幕数据库分发 | 超出个人使用范畴 |
| RL-05 | 向第三方平台回传/发送弹幕 | 一期不做（DEC-06），避免污染平台数据 |
| RL-06 | 内置公共资源站/在线播放源 | 会把工具变成盗版分发渠道 |
| RL-07 | 绕过平台限流、伪造设备指纹规避风控 | 属于对抗性行为 |
| RL-08 | 插帧/运动补偿等与定位无关的高功耗特性 | 非合规问题，但明确不做（`08` 文档） |

**代码审计要求**：`TC-SEC-005` 每次发版前检查仓库中无 RL-01/RL-02 相关实现。

## 3. 平台数据使用的自我约束

| 约束 | 具体做法 | 对应需求 |
| --- | --- | --- |
| 尊重接口频率 | 单集分片并发 ≤5，整源并发 ≤10，指数退避重试 ≤2 次 | `03` §9 |
| 强制缓存 | 弹幕缓存 12h（可配 2–24h），命中不再请求 | FR-DMK-012 / FR-GW-006 |
| 遵守官方条款 | 弹弹play 开放平台：禁止商业使用、批量抓取、规模下载 | `03` §1 |
| 不代持凭证 | 凭证存用户设备，网关不落盘 | FR-AUTH-005 / FR-GW-010 |
| 用户可关 | 每个源都可单独禁用，出网请求可全部关闭 | FR-SET-001 / NFR-SEC-003 |
| 不采集 | 无遥测、无第三方统计 SDK | NFR-SEC-003 |

## 4. 分发策略

| 渠道 | 内置平台适配器？ | 说明 |
| --- | --- | --- |
| App Store 版本 | ❌ 不内置 | 只带弹弹play 官方源 + **用户自填弹幕 API 地址**入口。这与 Senplayer / EPlayerX 等已上架应用的做法一致，审核风险最低 |
| 自托管网关（Docker） | ✅ 全部 | 由用户自行部署，适配器在用户自己的服务器上运行 |
| 开源仓库 | ✅ 代码开放 | 明确标注「仅供学习与个人使用」，并附免责声明 |

> 这是 DEC-02 的推荐值。同一套 `DanmakuProvider` 抽象同时支撑两种形态，客户端代码无差异——只是默认启用的源不同。

## 5. 开源与许可

| 事项 | 决定 |
| --- | --- |
| 本仓库许可证 | 建议 MIT 或 AGPL-3.0（AGPL 可防止他人闭源商用弹幕服务） |
| 第三方依赖 | 引入前检查许可证；VLCKit 为 **LGPL-2.1+**，动态链接使用并保留许可声明 |
| libass | MIT/ISC 系，注意其依赖（FreeType 等）的声明义务 |
| protobuf 定义 | 来自社区文档，注明出处 |
| 禁止 | 引入 GPL 传染性依赖到 App Store 目标（GPL 与 App Store 条款冲突） |

**发版前必须产出依赖许可证清单**并随包附带。

## 6. 隐私

| 项 | 处理方式 |
| --- | --- |
| 用户媒体文件 | 不上传、不索引到云端；Web 端本地文件仅在浏览器内处理 |
| 第三方平台凭证 | 仅存本地 Keychain / 加密存储；单次请求透传；日志脱敏 |
| 观看记录 | 默认仅本地；开启 iCloud 同步后存于用户自己的 iCloud |
| 崩溃与诊断 | 默认关闭上报；用户主动导出时自动脱敏 |
| 儿童隐私 | 不采集数据，无社交功能 |

隐私政策要点：**「我们不收集任何数据」必须是事实陈述，而不是营销话术**——依赖清单里不能出现统计 SDK。

## 7. 风险登记册

| ID | 风险 | 概率 | 影响 | 应对 |
| --- | --- | --- | --- | --- |
| R-01 | 平台接口改版导致某源失效 | **高** | 中 | 每日探活 + 自动降级 + 自定义 API 兜底（`05` §7） |
| R-02 | 优酷 MTOP 签名变更 | 高 | 低 | 该源标为易失效，失败即整源降级，不阻塞 |
| R-03 | B 站 WBI 签名算法调整 | 中 | 中 | 密钥每日刷新 + 结构断言 + 探活告警 |
| R-04 | 跨平台剧集映射准确率不达标 | 中 | **高** | 时长校验 + 用户手动绑定并持久化 + 媒体服务器元数据优先 |
| R-05 | 时轴错位导致体验崩塌 | 中 | **高** | 手动偏移（P0）+ 时长缩放 + 自动对齐（M3） |
| R-06 | tvOS 4K 弹幕渲染性能不达标 | 中 | 高 | 先 CoreAnimation 验证，不达标转 Metal；密度限流兜底 |
| R-07 | VLCKit 在 tvOS 上的已知缺陷（复用播放器时视频输出不重新挂载，表现为有声黑屏） | 中 | 高 | 切片源时**销毁并重建播放器实例**而非复用；纳入 TC-PLY 回归 |
| R-08 | App Store 审核因弹幕来源被拒 | 中 | 高 | 采用 DEC-02 分发策略：上架版不内置抓取 |
| R-09 | 用户凭证泄露 | 低 | **高** | Keychain + 不落盘 + 日志脱敏 + 安全用例 TC-SEC-001~004 |
| R-10 | 公网自托管网关被滥用 | 中 | 中 | 强制 Token（FR-GW-004）+ 限流 + 文档提示不要公开分享地址 |
| R-11 | 弹弹play 开放平台配额或政策变化 | 低 | 高 | 缓存 + 自定义 API + 多源并存，不单点依赖 |
| R-12 | 依赖许可证冲突（LGPL/GPL） | 低 | 高 | 依赖引入前审查；VLCKit 动态链接 |
| R-13 | 大量弹幕导致内存问题（长片 + 多源） | 中 | 中 | 分段加载 + 密度限流 + 内存用例 TC-PERF-007/008 |
| R-14 | 多 AI 协作导致契约漂移 | **高** | 中 | 契约先行 + `kanata-contract` Skill + 交付说明必填契约变更 |
